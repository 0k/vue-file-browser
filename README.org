#+TITLE: @0k/vue-file-browser

* Purpose and delivery

A reusable Vue 3 folder browser with the look of GNOME Files' list view: a
slim header bar with an Up button, a clickable path bar and a hidden-files
toggle, then compact rows with each entry's icon, name, size and
modification date. It draws no box of its own and fills whatever space the
host gives it, from a full page to a fixed-height panel. Fed by a live host
source, it follows folder changes without a Reload button and without
fetching anything itself.

The package owns sorting, formatting, rendering, loading states and
selection. Hosts own fetching, change notification, authorisation, routing
and history: they supply either ~load(path)~ or ~feed(path, sink)~ and turn
the ~open-folder~ / ~open-file~ events into navigation. MIT licensed;
Vue ~^3.5.0~ is a peer; there are no runtime dependencies.

Run ~npm install~, ~npm run check~, then ~npm run pack~. The last command
builds and produces ~artifacts/0k-vue-file-browser-0.1.0.tgz~ without
publishing. A consumer copies that artifact into its ~frontend/vendor/~ and
installs it as ~file:vendor/0k-vue-file-browser-0.1.0.tgz~ with its normal
npm workflow. This project never edits or vendors into consumer
repositories.

* Exact exports

#+begin_src typescript
type FolderEntryKind = 'file' | 'dir' | 'other';
interface FolderEntry {
  name: string;
  kind: FolderEntryKind;      // after following symlinks
  symlink: boolean;
  size: number | null;        // bytes, files only
  modified: number | null;    // Unix seconds
  mime: string | null;
}
interface FolderListing {
  path: string;               // absolute
  parent: string | null;      // null at the root
  entries: FolderEntry[];
  truncated: boolean;
}
type FolderLoader = (path: string) => Promise<FolderListing>;
interface FolderFeedSink { listing(listing: FolderListing): void; error(message: string): void }
type FolderFeed = (path: string, sink: FolderFeedSink) => () => void;  // returns stop
interface PathSegment { label: string; path: string }

function sortEntries(entries: FolderEntry[]): FolderEntry[];
function formatSize(bytes: number): string;
function formatModified(seconds: number, now?: Date): string;
function joinPath(dir: string, name: string): string;
function pathSegments(path: string, home?: string | null): PathSegment[];
const FileBrowser: Component;
#+end_src

~sortEntries~ puts folders first, then sorts by name in natural,
case-insensitive order (~b2~ before ~b10~), breaking ties on the raw name.
~formatSize~ uses decimal units like GNOME: ~1 byte~, ~512 bytes~,
~4.1 kB~, ~12.3 MB~. ~formatModified~ gives ~Today 14:32~,
~Yesterday 09:05~, otherwise the full date ~12 Oct 2026~, as GNOME Files does.
~pathSegments~ starts with a ~~~ segment for a path at or under ~home~,
else with ~/~.

The home segment of the path bar shows a house icon.

* Component

#+begin_src typescript
{
  path: string;               // absolute folder to show
  load?: FolderLoader | null; // fetch on demand…
  feed?: FolderFeed | null;   // …or receive every listing (takes precedence)
  select?: string | null;     // entry name to highlight and scroll to
  home?: string | null;       // collapsed into the first path-bar segment
  homeLabel?: string;         // default '~'
  showHidden?: boolean;       // default false, v-model:showHidden
}
// emits
'open-folder': [path: string]
'open-file': [path: string, entry: FolderEntry]
'update:showHidden': [value: boolean]
#+end_src

The browser takes its listings from exactly one source. With ~feed~, it
starts the feed on mount, restarts it when ~path~ (or the feed) changes,
stops it on unmount, and fetches nothing itself: each ~sink.listing~
replaces the rows in place (the selection is scrolled to only on the first
listing), each ~sink.error~ shows the message, and a later listing clears
it. Without a feed, ~load~ runs on mount and whenever ~path~ changes.
Retry restarts the source. Results of a superseded start, or arriving
after unmount, are ignored.
Keep ~load~ and ~feed~ as stable references: a new function identity for the
active source restarts it.

A rejected load shows the error's message verbatim with a Retry button.
Entries whose name starts with a dot are hidden unless ~showHidden~; a
folder holding only hidden entries offers a Show hidden files button that
emits ~update:showHidden~; the host must update ~showHidden~ to reveal them.
Clicking a folder, an ancestor in the path bar, or Up emits ~open-folder~;
clicking any other entry emits ~open-file~ with its absolute path. The
component keeps no history. Below 448 px of width the Size and Modified
columns are dropped.

There is no Reload button: changes arrive through ~feed~.

* Styling

Every rule hangs from ~.vfb-root~. Override these variables on it (defaults
follow the libadwaita dark palette; the widget draws no border and its own
background is transparent): ~--vfb-bg~, ~--vfb-sticky-bg~ (behind the
sticky column header: set it to the page colour), ~--vfb-fg~,
~--vfb-dim-fg~, ~--vfb-border~, ~--vfb-hover-bg~, ~--vfb-accent~,
~--vfb-accent-fg~, ~--vfb-selected-bg~, ~--vfb-folder-icon~,
~--vfb-file-icon~, ~--vfb-error-fg~, ~--vfb-font-family~ (default ~"Ubuntu
Sans Mono", "Ubuntu Mono", monospace~), ~--vfb-font-size~ (12.5 px),
~--vfb-row-height~ (24 px), ~--vfb-gutter~, ~--vfb-column-gap~.
