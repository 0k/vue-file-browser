#+TITLE: @0k/vue-file-browser

* Purpose and delivery

A reusable Vue 3 folder browser with the look of GNOME Files' list view: a
slim header bar with an Up button, a clickable path bar and a hidden-files
toggle, then compact rows with each entry's icon, name, size and
modification date, under sortable, resizable column headers. It draws no
box of its own and fills whatever space the host gives it, from a full page
to a fixed-height panel. Fed by a live host source, it follows folder
changes without a Reload button and without fetching anything itself.

The package owns sorting, formatting, rendering, loading states, column
resizing and selection. Hosts own fetching, change notification,
authorisation, routing, history and persistence: they supply either
~load(path)~ (fetched on demand) or ~feed(path, sink)~ (pushes every
listing, e.g. from a live channel), and turn the ~open-folder~ /
~open-file~ events into navigation.

Hosts must bind ~v-model:sort~, ~v-model:show-hidden~ and
~v-model:column-widths~ for the controls to take effect. The component keeps
no local state for these settings; the bindings apply its update events to
host-owned values. Hosts may also persist these values.

MIT licensed; Vue ~^3.5.0~ is a peer; there are no runtime dependencies.

Run ~npm install~, ~npm run check~, then ~npm run pack~. The last command
builds and produces ~artifacts/0k-vue-file-browser-0.1.0.tgz~ without
publishing. A consumer copies that artifact into its ~frontend/vendor/~ and
installs it as ~file:vendor/0k-vue-file-browser-0.1.0.tgz~ with its normal
npm workflow. This project never edits or vendors into consumer
repositories.

* Exact exports

#+begin_src typescript
type FolderEntryKind = 'file' | 'dir' | 'other';
interface FolderEntry {
  name: string;
  kind: FolderEntryKind;      // after following symlinks
  symlink: boolean;
  size: number | null;        // bytes, files only
  modified: number | null;    // Unix seconds
  mime: string | null;
}
interface FolderListing {
  path: string;               // absolute
  parent: string | null;      // null at the root
  entries: FolderEntry[];
  truncated: boolean;
}
type FolderLoader = (path: string) => Promise<FolderListing>;
interface FolderFeedSink { listing(listing: FolderListing): void; error(message: string): void }
type FolderFeed = (path: string, sink: FolderFeedSink) => () => void;  // returns stop
type FolderSortKey = 'name' | 'size' | 'modified';
interface FolderSort { key: FolderSortKey; descending: boolean }
interface FolderColumnWidths { size: number; modified: number }  // px
interface PathSegment { label: string; path: string }

const DEFAULT_SORT: Readonly<FolderSort>;                  // name, ascending; frozen
const DEFAULT_COLUMN_WIDTHS: Readonly<FolderColumnWidths>; // 96, 136: used only when measuring is impossible; frozen
const MIN_COLUMN_WIDTHS: Readonly<FolderColumnWidths>;     // 56, 72; frozen
const MAX_COLUMN_WIDTH: number;                  // 480
function clampColumnWidth(column: keyof FolderColumnWidths, width: number): number;
function sortEntries(entries: FolderEntry[], sort?: FolderSort): FolderEntry[];
interface SizeParts { whole: string; fraction: string; unit: string }
type ModifiedParts =
  | { form: 'relative'; word: 'Today' | 'Yesterday'; time: string }
  | { form: 'date'; day: string; month: string; year: string };
function sizeParts(bytes: number): SizeParts;
function modifiedParts(seconds: number, now?: Date): ModifiedParts;
const MONTHS: readonly string[];
function formatSize(bytes: number): string;
function formatModified(seconds: number, now?: Date): string;
function joinPath(dir: string, name: string): string;
function pathSegments(path: string, home?: string | null): PathSegment[];
const FileBrowser: Component;
#+end_src

~sortEntries~ puts folders first, then sorts by the sort key: names in
natural, case-insensitive order (~b2~ before ~b10~, ties on the raw name);
sizes and dates numerically, entries without one last, ties by name.
~formatSize~ uses decimal units like GNOME: ~1 byte~, ~512 bytes~,
~4.1 kB~, ~12.3 MB~. ~formatModified~ gives ~Today 14:32~,
~Yesterday 09:05~, otherwise the full date ~12 Oct 2026~, as GNOME Files does.
~sizeParts~ and ~modifiedParts~ return the same values split for column
alignment, which the browser renders slot by slot with equal-width digits
(~tabular-nums~), so the alignment holds in any font: sizes as a number
right-aligned on 3 digits, a one-decimal slot (blank for bytes) and the
unit starting in one column; dates right-aligned as a whole, each form
aligned only with itself — times under times, and for full dates the day
padded to 2 digits, the month in a slot as wide as the widest month name
(measured in the current font), and the year.
~pathSegments~ starts with a ~~~ segment for a path at or under ~home~,
else with ~/~.

The home segment of the path bar shows a house icon.

* Component

#+begin_src typescript
{
  path: string;               // absolute folder to show
  load?: FolderLoader | null; // fetch on demand…
  feed?: FolderFeed | null;   // …or receive every listing (takes precedence)
  select?: string | null;     // entry name to highlight and scroll to
  home?: string | null;       // collapsed into the first path-bar segment
  homeLabel?: string;         // default '~'
  showHidden?: boolean;       // default false, v-model:showHidden
  sort?: FolderSort;          // default DEFAULT_SORT, v-model:sort
  columnWidths?: FolderColumnWidths | null; // default null: fit the content; v-model:columnWidths
}
// emits
'open-folder': [path: string]
'open-file': [path: string, entry: FolderEntry]
'update:showHidden': [value: boolean]
'update:sort': [value: FolderSort]
'update:columnWidths': [value: FolderColumnWidths]
#+end_src

The browser takes its listings from exactly one source. With ~feed~, it
starts the feed on mount, restarts it when ~path~ (or the feed) changes,
stops it on unmount, and fetches nothing itself: each ~sink.listing~
replaces the rows in place (the selection is scrolled to only on the first
listing), each ~sink.error~ shows the message, and a later listing clears
it. Without a feed, ~load~ runs on mount and whenever ~path~ changes.
Retry restarts the source. Results of a superseded start, or arriving
after unmount, are ignored.
Keep ~load~ and ~feed~ as stable references: a new function identity for the
active source restarts it.

With the bindings above, the controls behave as follows.
Clicking a column header sorts by it (Modified starts newest first); a
second click reverses the order. Dragging the separator on the left of Size
or Modified resizes that column (starting from its current width), within ~MIN_COLUMN_WIDTHS~ and
~MAX_COLUMN_WIDTH~; Name takes the remaining space. The header and every
row share one column template, so labels and values stay aligned.
Without ~v-model:column-widths~, the resize preview snaps back on release.
A rejected load shows the error's message verbatim with a Retry button.
Entries whose name starts with a dot are hidden unless ~showHidden~; a
folder holding only hidden entries offers a Show hidden files button that
emits ~update:showHidden~; the host must update ~showHidden~ to reveal them.
Clicking a folder, an ancestor in the path bar, or Up emits ~open-folder~;
clicking any other entry emits ~open-file~ with its absolute path. The
component keeps no history. Below 448 px of width the Size and Modified
columns are dropped.
There is no Reload button: changes arrive through ~feed~.

* Styling

Every rule hangs from ~.vfb-root~. Override these variables on it (defaults
follow the libadwaita dark palette; the widget draws no border and its own
background is transparent): ~--vfb-bg~, ~--vfb-sticky-bg~ (behind the
sticky column header: set it to the page colour), ~--vfb-fg~,
~--vfb-dim-fg~, ~--vfb-border~, ~--vfb-hover-bg~, ~--vfb-accent~,
~--vfb-accent-fg~, ~--vfb-selected-bg~, ~--vfb-folder-icon~,
~--vfb-file-icon~, ~--vfb-error-fg~, ~--vfb-font-family~ (default ~"Noto Sans", Cantarell, sans-serif~;
alignment never needs a monospace font), ~--vfb-font-size~ (13 px),
~--vfb-row-height~ (24 px), ~--vfb-gutter~ (also the gap between columns).

Without ~columnWidths~, Size and Modified are as wide as their widest
possible content in the current font (~999.9 bytes~, a full date, a
~Yesterday~ time, and their labels), measured once mounted and again when
fonts finish loading, so the space between two columns is just the gutter.
